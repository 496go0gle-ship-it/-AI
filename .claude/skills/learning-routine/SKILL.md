# learning-routine — 学習セッションの統括

## 目的
自作プロダクト（このリポジトリ＝教育伴走型AI / ZPD推論エンジン）を題材に、「自作コードの構造を理解し、意図的に改善・拡張できる状態」になるための学習セッションを1回ぶん運営する。**AIが結論を先に出すのではなく、オーナー本人に考えさせ・説明させる**ことを最優先にする。

オーナーとプロダクトの実態：
- 東大院・修士（物理）、28卒エンジニア就活中。Python中心・vibe coding寄り、他言語は表面的。
- プロダクト：FastAPI + 静的フロント、Render公開、**実ユーザーゼロの公開デモ**。
- 構成：`main.py`（配線）/ `api/routes.py` / `services/zpd_service.py`（`calculate_zpd`, 正答率50%基準）/ `services/llm_service.py`（`generate_next_question`, Gemini呼び出し, gemini-2.5-flash）/ `schemas/` / `static/`。
- 狙い：このプロダクトを (A) 就活で語れる実績 と (B) 在学中の収益源 の両取りにする。
- 当面のゴール：10月までに「自作コードの構造を理解し、意図的に改善・拡張できる状態」になる。

## 学習の枠組み（既存・変えない）
**理解 → 監査 → 改善 → 発展 → マネタイズ** のループ。
- Phase 0（北極星）/ 1（全体構造）: 完了。
- Phase 4（リスク&コスト監査）: 前倒し実施済み（共有鍵露出を発見 → 公開デモ化で認証廃止 → slowapi起因の500も解消済み）。
- **現在地: Phase 2-3（各要素の役割を理解し、詳細を追う・壊す）。最初の対象は `services/zpd_service.py` の `calculate_zpd()`。**

## 発動条件
「今日の学習」「学習を始める」「learning routine」「次のフェーズ」「学習を進めたい」等。学習セッションの統括スキル。

## 1回のセッションのワークフロー
**重要：一度に詰め込まない。各ステップでオーナーの応答を待ってから次へ進む。**

### ステップ0: 視界合わせ
- **market-scan スキルを呼び**、その日の市場レポートを冒頭で提示する。learning-routine 経由で呼んでいることと、本日の回のテーマ（理解／監査／改善／発展／マネタイズ）を market-scan に伝え、5節「自プロダクトへの示唆」をその日の作業対象コードに寄せてもらう。
- market-scan が使えない／見つからない場合はスキップし、「市場スキャンは今回スキップします」と一言伝えて先に進む。

### ステップ1: 今日の範囲を決める
- `docs/learning_log.md` を読み、前回どこまで進んだか・次回の入口を確認する（無ければ「初回」として現在地＝`calculate_zpd()` から始める）。
- 今日扱う範囲を**小さく**提案する（一度に1関数〜数行）。**オーナーの合意を取ってから**先へ進む。

### ステップ2: オーナーに先に説明させる（説明し返しチェック）
- 対象コードについて、**こちらから先に解説しない。**
- まずオーナーに「このコードが何をしていると思うか」を説明させる。**応答を待つ。**

### ステップ3: 実装と照合
- オーナーの説明と実際の実装のズレを、**行番号付き**で指摘する。
- 関連する呼び出し元／呼び出し先も示す。
- **コードは記憶で書かず、実ファイルから正確に引用する。**

### ステップ4: 改善案
- 改善余地があれば出す。ただし必ず「**今やる / 保留**」を区別し、保留はその理由も書く。
- 一度に変えすぎない。**実際の変更はオーナーが判断する。**

### ステップ5: 締め（進捗まとめ）
- その回の学びを `docs/learning_log.md` に追記する（無ければ作る）。記録項目：
  - 日付 / 扱った範囲 / オーナーの当初の理解 / 実装との主なズレ / 決めたこと / 保留にしたこと / 次回の入口
- さらに「持ち帰り」を2つ生成：
  - 就活で言える一文 1つ（実態の範囲で。誇張しない）
  - 発信ネタ（note/X）1つ（タイトル案レベルで可）

## 品質ルール（厳守）
- **オーナーを飛ばさない。** AIが結論を先に出すのではなく、本人に考えさせ・説明させることを優先する（ステップ2を省略しない）。
- **小さく刻む。** 1セッションで扱うのは1関数〜数行まで。
- **コードは記憶でなく実ファイルから正確に引用する。** 行番号を付ける。
- **改善案は「今やる/保留」を必ず区別する。** 変更の実行はオーナーの判断を待つ。
- **プロダクトを誇張しない。** 実態は実ユーザーゼロの公開デモ。就活の一文も実態の範囲で書く。
- **進捗は必ず `docs/learning_log.md` に残し、次回はそこから再開する。**

## market-scan との関係
- このスキルはセッションの**統括役（親）**。冒頭（ステップ0）で market-scan を呼ぶ。
- **使い分け：** 「市場だけ見たい」ときは market-scan を**単独**で使う。「コード学習をやる」ときはこの learning-routine を使う（その中で market-scan が自動で走る）。
