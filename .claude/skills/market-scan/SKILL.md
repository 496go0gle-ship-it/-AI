# market-scan — 学習冒頭の市場スキャン

## 目的
コード学習に入る前の「視界合わせ」。教育伴走型AI（ZPDチューター型）の需要を、現在のIT市場と日本の教育市場に照らして**短く**分析したレポートを1枚出す。毎回フルセットを垂れ流さず、その日の問いに絞る。画面1〜2スクロールで読み切れる量に収める。

このプロダクト（このリポジトリ）の実態：
- FastAPI + 静的フロント、Render公開、**実ユーザーゼロの公開デモ**。
- ZPD（発達の最近接領域）を定量計算し、Gemini API でパーソナライズ問題を生成するバックエンド。
- オーナーは東大院・修士（物理）の28卒エンジニア就活生。Python中心・vibe coding寄り。
- 狙い：このプロダクトを (A) 就活で語れる実績 と (B) 在学中の収益源 の両取りにする。

## 発動条件
- ユーザーが「学習を始める」「今日の学習」「market scan」「市場スキャン」「市場の状況を見たい」等と言ったとき。
- learning-routine スキルの**ステップ0**として呼ばれたとき。
- 単独起動（市場だけ見たい）と learning-routine 経由の両方で動くこと。learning-routine 経由のときは、その回のテーマ（理解／監査／改善／発展／マネタイズ）を受け取り、5節「自プロダクトへの示唆」をその回の作業対象コードに寄せる。

## ワークフロー

### Step 1. 今日の問いを決める
下のローテーションから**1つだけ**選ぶ（ユーザーが指定したらそれを優先）。前回どれを扱ったかは `docs/market_scans/` の直近ファイルを見て、被らないものを選ぶ。

問いローテーション：
1. 誰が今この種のプロダクトに金を払っているか（B2C学習者 / 塾 / 学校 / 親）
2. 競合（Monoxer, atama+, スタディサプリ, Khanmigo 等）は何を解いていて、何を解き残しているか
3. 個人開発・小資本で入り込める隙間はどこか
4. 日本特有の論点（教育格差、地方、GIGAスクール後、塾DX）で需要が立つ場所
5. 就活の文脈：この領域でエンジニアに求められている力は何か

### Step 2. 最新情報を取りに行く
- **web 検索が使えるなら必ず使う**。市場の現状（IT側＝小規模開発者に効くAI動向／教育側＝日本のEdTech・学習市場の直近の動き）を最新で取る。出典URLと日付を控える。
- web 検索が使えない場合は、その旨を明示し、各シグナルに `[未検証・要確認]` ラベルを付ける。記憶ベースの一般論で断定しない。

### Step 3. レポートを書く（下記の7節構成）
短く。各節は数行。今日の問いに関係ない節は1〜2行に圧縮してよい。

### Step 4. 保存して提示
- `docs/market_scans/YYYY-MM-DD.md` として保存（ディレクトリが無ければ作る）。同日に再実行する場合は `YYYY-MM-DD-2.md` のように連番。
- 過去回と比較できるよう、前回からの差分があれば最後に一言添える（「前回比：〜」）。
- チャットには全文ではなく要点（今日の問い＋持ち帰り）を出し、「全文は docs/market_scans/YYYY-MM-DD.md」と案内する。

## 品質ルール（厳守）
- **古い知識で語らない。** 市場の現状は web 検索が使えるなら必ず最新を取りに行く。使えない場合は「未検証・要確認」と明示する。
- **ハイプ禁止。** 「AIは伸びている」式の一般論は書かない。本質（誰の・何の課題が・なぜ金になるか）で書く。
- **プロダクトを誇張しない。** 実態は実ユーザーゼロの公開デモ。背伸びした主張（「ユーザーに使われている」等）はさせない。就活の一文も実態の範囲で書く。
- **短く。** 冒頭で読むもの。長文レポートにしない。画面1〜2スクロール。
- **推測と事実を必ず分ける。** 出典付き＝確証、それ以外＝推測ラベル。
- **保存を忘れない。** `docs/market_scans/YYYY-MM-DD.md` に必ず残し、過去回と比較できる状態を保つ。
